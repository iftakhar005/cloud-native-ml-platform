# Results log

Every number here comes with what it does and does not mean. Reproduce with
`python -m thikana.training.train` then `python -m thikana.training.evaluate_handwritten`.

## Current state (2026-10-26)

| Evaluation set | Rule baseline | CRF v1 | CRF v2 (+gazetteer) |
|---|---|---|---|
| Synthetic dev (600 addresses) | 0.886 | 0.981 | 0.984 |
| Hand-written set (70 addresses, 301 entities) | 0.852 | 0.932 | 0.946 |
| Gap (synthetic minus hand-written) | +0.034 | +0.048 | +0.038 |

All values are entity-level micro F1 (start, end and label must all match).

### How to read this

- **Synthetic dev** is generated by the same code that generated the training
  data. It measures how well the model learned the generator, not addresses.
- **The hand-written set is NOT real data.** It was written by an AI assistant
  from general knowledge of Bangladeshi addresses (see `data/handwritten/README.md`).
  The same author wrote the generator, so the author's idea of an address is in
  both. The gap is probably a LOWER BOUND on the real synthetic-to-real gap.
  The prediction before scoring was a larger drop (CRF into the 0.80s); it was
  smaller, consistent with that non-independence.
- **No real address has been measured yet.** `data/real/` is empty.
- With 70 addresses the uncertainty is wide. Per-label and per-style numbers
  rest on 1-13 entities or addresses and are directional only. DIVISION has 2
  gold entities.

### Comparisons (paired bootstrap, 95% interval, micro F1)

| Comparison | Synthetic dev | Hand-written |

| CRF v1 minus rule baseline | +0.095 [+0.081, +0.109] | +0.081 [+0.038, +0.125] |
| CRF v2 minus CRF v1 | +0.003 [-0.001, +0.008] | +0.014 [+0.000, +0.029] |

The CRF beating the baseline holds on both sets. v2 over v1 is not
established: the hand-written interval touches zero, and the set is small and
not independent. v1 stays the working model.

## Why the 16 hand-written errors (CRF v1) happen

| Cause | Addresses | Fixable by |
|---|---|---|
| Keywords the generator never wrote: `Apartment`, `Plot`, `Road No.`, `Section` | 4 | more keyword variety |
| Village introducers never wrote: `Village:`, `Gram:`, `Vill-`, `P.O-`, `P.S-`, `থানা:` | 4 | more introducer variety |
| A lone `Dhaka` labelled DIVISION (decision D1), also the top error on synthetic dev | 3 | targeted D1 work |
| Landmarks: only 5 landmark names exist in the generator, so it memorised names | 2 | many more landmark phrases |
| Postcode or district first (`1212, Dhaka, ...`): positional shortcut, first digits = HOUSE | 2 | order variety |
| An unseen upazila with no introducer labelled DISTRICT | 1 | more upazila coverage |

On reversed-order addresses the regex baseline (1.000) beats the CRF (0.759):
the rules do not care about order, the model learned a position.

## Rules for the next iteration

This hand-written set is now SPENT for tuning: its errors will drive generator
changes, so a further improvement measured on it would be circular. After the
generator changes, write a fresh `addresses_v2.txt` and report that number.
Real addresses, once collected, supersede both.
